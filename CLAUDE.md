# Pocket Passer (pocketpasser.io)

A first-person browser QB game. You memorize a play, take the snap, and throw (early, or at the freeze when the real QB released it). Your decision is scored in EPA against the pro's actual throw. A home page offers the Daily 6 (with a public leaderboard and, signed in, a player page) (the same 6 plays for everyone each day, with a leaderboard), practice rounds, versus mode (six snaps of one real QB, best score per QB kept in localStorage `qbcam.vs.<name>`), and a tutorial. Esc opens a pause menu (resume / restart play / sound / home); every round ends on a deliberately simple results page, in this order: total EPA vs the pro, your rank with an estimated distribution of quarterbacks ("better than about N% of quarterbacks"; the real leaderboard below says players; histogram from the rank cut-offs' percentiles, `DIST_CDF`, your bar highlighted, "top N%"), the leaderboard (where one exists), then the play-by-play dumbbell (you vs the pro per snap). KPIs, tendencies and the every-throw list were removed at the user's request; the leaderboard card only shows where a board exists.

## Run / test
```bash
python3 build.py
open beat-the-pro-qb-cam.html            # or: python3 -m http.server, then open fp2.html
npm i three@0.160.0 playwright && npx playwright install chromium
python3 tests/e2e_accounts.py            # account state machine on a fake Supabase + fake Google script: expects 17/17 passed
python3 tests/e2e_tutorial.py            # prints ['pre', 'pre2', 'pre3', 'decide', 'done'] ['daily', True, False, True] then [] (no errors)
```
Every round waits for the plays file (`REAL.ready`/`REAL.done`; "Loading plays…"): the tutorial used to start before it arrived on slow phones and crashed (error reports, iPhones). http:// on pocketpasser.io redirects to https:// (the Google sign-in needs `crypto.subtle`, which only exists on secure pages; without it sign-in falls back to the OAuth popup). build.py inlines the plays into the standalone file by rewriting the `REAL.ready=fetch('real_plays.json')…` line and asserts it did. Robustness: `loop()` schedules the next frame first and runs `frame()` in try/catch (one throwing frame used to stop the loop for good: players saw a frozen field with no text). Errors (frame, window, promise, WebGL context loss) go to Supabase `client_errors` via `reportErr` (insert-only table, `supabase/client_errors.sql`; max 4 per page load, deduped; context = where | phase | mode | play | touch/mouse | size | build time). Read them with the Management API: `select at,msg,ctx,ua from client_errors order by at desc`. A lost WebGL context shows "The graphics reset · Tap to reload" (`#glLost`). Performance: phones render at most 1.5x pixel ratio; `adaptRes` drops the ratio in 0.25 steps (to 1x) when frames run under ~45 fps for 2.5 s; the scene is drawn every 6th frame behind the results page and every 2nd behind the phone home page; no backdrop blur on phones behind the loss banner. `window.__perf={n:0,upd:0,ren:0,maxUpd:0}` collects frame timings. Debug hooks on `window`: `__camOv` (set to a function(cam,now) to steer the camera; trailer capture), `__ddFlash()`, `__S` (state), `__PLAYS`, `__load(i)`, `__force(x,y,type,kind,sub,yac)` (force an outcome), `__showResults()`, `__setArt(style)`, `__atlas(style,side,num)`.

## Model in one paragraph
Throw = target spot + type (fastball: 0.05 + d/23 s; touch: 0.15 + d/18.5 s; calibrated to real air times). The receiver who can reach the spot is found with a route-gap model and a "read it, brake, come back" redirect model; the smaller gap wins, and a reversal means "thrown behind". After the release, defenders keep their real tracking for a reaction delay (0.22 s facing the QB to 0.62 s back turned on real plays), then close at 85% of their sprint speed. **Catch / INT odds** (`cpOdds`) are a multinomial logistic model fit by `tools/fit_completion.py` to ~14k real 2023 throws on the game's own features (receiver gap, defender gap after closing, tip risk, air distance, depth, throw type); held-out log loss 0.58 vs 0.87 for the old hand-tuned odds, calibrated by depth; a ball the receiver can't reach still fades to no catch between 2 and 4 yd off his path. **Expected points** (`EP`) is a down x distance x yards-to-goal table fit by `data/fit_ep.py` to nflverse EP on 118k plays (2023-25); held-out RMSE 0.35 vs 0.62 for the old formula. Rank cut-offs come from `tools/calibrate_ranks.js` (pros' real throws sit around the 78th percentile of catchable throws = "NFL starter"). After each snap the review shows the model's best read (green BEST marker) and one sentence on why it beat yours (`whyBest`). A drop is the leftover incompletion when the ball was reachable and no tip or breakup won the roll. Tools: `tools/model_harness.js` loads the game's model into Node; `tools/dump_features.js` exports features for refitting.

## Decisions the user has made (don't undo without asking)
- **Aiming = click a spot on the field (floor).** The user tried and rejected: chest-height aim, a dotted arc/side-view inset, route-snap with a ghost receiver, and trajectory hoops. Keep it simple.
- **Animations:** keep the current ones. A slapstick pass was tried and reverted.
- **Art style: pixel art only** (user decision). The style chooser and the V key were removed; `ART.cur` is fixed to `pixel` (the other styles remain in code, unused). Sideline figures, team banners and the down box use the same pixelize pass (`pixelCanvas`/`pixTex`); the crowd and LED ribbons are low-res canvases with nearest-neighbour magnification. Type: **Press Start 2P** for display and **VT323** for text, declared as `Retro`/`RetroText` @font-face (gstatic URLs, `size-adjust` so sizes match the old fonts). UI chrome is 8-bit: square corners, stepped pixel frames (offset box-shadows), hard drop shadows, bevelled buttons. Exception the user asked for: the tutorial card and the first-visit question are see-through "liquid glass" (blur + rim highlight) inside the pixel frame. The 3D view renders at full resolution: a low-res pixelated render was tried and rejected (field text and arrows looked fuzzy).
- No photos of real people (QBs) in the game.
- Branding: the site is **pocketpasser.io**; "Beat the Pro" is retired from the landing page (the in-game result line "You beat the pro by…" stays). Landing copy (user's, lightly polished): "Think you can outread an NFL quarterback? Real NFL plays. Real NFL coverages. Prove you'd be Brady — if only you were 6-4, 225." Design is deliberately restrained: wordmark, one headline, one primary button, a plain list of other modes.
- Stadium: straight stands end exactly at the four corners and curved `cornerBowl` sections (same tiers, crowd, LED, facade, roof) fill them, so the bowl is continuous.
- Home page: no mascot. A pixel-art mascot was tried and removed at the user's request.
- Home page is minimal: wordmark, headline, lede "Replay real NFL plays. Prove you'd be Brady, if only you were 6'4" 225 lbs.", one big **Play today's 6 snaps** button, a row of text links (Practice, Versus a real QB, Tutorial, Drew Bledsoe mode), sound/announcer toggles.
- **One play pool, no fake plays:** every round draws from all real plays: the highlight clips plus, when `data/bdb_plays/index.json` is served, the full 2023 season (no Highlights/Season switch). The hand-made drill plays still live in `index.html` for the 2D prototype and tests but are never used in a round.
- **First visit / tutorial:** on a first visit, any way into the game (Today's 6, Practice, Versus, Drew Bledsoe mode; `firstThen`) first asks "Want a quick tutorial?" (green Yes / see-through No, saved as `qbcam.visited`; No carries on to whatever was clicked); a Tutorial link is on the home page. The tutorial is 3 real highlight plays (`TUT_KEYS`, excluded from other rounds). Play 1 (`TUT_KEY`, Mahomes to Hill 2018, 4.2 s in the pocket) is guided: card 1 "This is a real NFL play", straight into card 2 "At the snap, you become the quarterback" ("Get ready to memorize the routes…"), the route countdown, then ~0.8 s into the first-person view the play pauses for card 3 "Find your read" (look controls; an in-play hint was rejected as too fast), then at the freeze "The time is now" (no clock, green ring = best spot in view), then the score card. Plays 2-3 (Brees 2018, Stafford 3rd & 3) run at game tempo: one "Now at real tempo" card, the real clock (3 s / 5 s phones), no ring. Then the normal results page ("Tutorial complete" → Play today's 6). **In the tutorial any throw with over a 40% catch chance is always caught** (user's rule, so beginners aren't discouraged; the override is in `startThrow`).
- **No auto-advance:** after a play nothing moves on by itself; pulsing text in the middle of the screen says "Press Space for the next play" (phones: "Tap for the next play"; a tap anywhere on the field works). Moving on ends the win/loss banner, blur and confetti at once.
- **Field:** `buildField` always draws the whole field (both end zones + a 2 yd border) whatever the line of scrimmage; it used to cover only 30 yd behind to 82 yd ahead, so a play from deep in your own end had no far end zone and the grass ran on.
- Stadium: all stadium meshes are in the `STAD` group, slid along the field per play (`placeStadium`) so the end stands always sit just past the end zones (red-zone plays used to show 70 yd of empty grass).
- Rank names come from average EPA per snap vs the pro (`TIERS` in fp2_src.html, Hall of Famer down to Guy in Section 300). Cut-offs are first guesses; recalibrate from real play.
- Sound: one setting (`H.sound`, saved as `qbcam.sound`) controls everything from page load; all audio goes through `AU.master`.
- No text-to-speech anywhere (user decision): every voice is a recording. Unrecorded announcer lines are silent; with no cadence clips there is no call and the countdown snaps the ball.
- Home music: `audio/music/home.mp3` = the user's own "Gridiron Fanfare" (made with Suno; free-plan Suno is non-commercial use). Loops on the home page, fades out when a round starts, restarts from the top on returning home. Without the file the old synthesized brass theme plays.
- Announcer: discrete soundbites only (no live TTS inference). `announcer_lines.json` = every line (ID `<event>_<n>`); `audio/announcer/<ID>.mp3` is the recording (lines without one are silent); build.py inlines them and writes `audio/announcer/todo.csv` (lines still unrecorded). Render with `tools/gen_announcer.py` (ElevenLabs; key from `ELEVENLABS_API_KEY`, voice `zvaUoS1oKNnOuzT312WU`; `--only` takes ID prefixes). Events: round start, pre-snap by situation, outcome at the catch point, verdict vs the pro (`blunder` at ≤ −1.5 EPA), final rank. The user chose to record only play-by-play, blunders and pre-snap lines so far.
- Dropback commentary (`dropback` lines) plays 0.3 s after the snap, chosen ONLY from recordings strictly shorter than the time left before the freeze (minus 0.25 s); stops on an early throw. At the freeze, `AU.slowmo()` plays a tape-stop/whoosh and muffles the crowd (low-pass on `crowdBus`); `AU.unslow()` on the throw.
- Recorded cadences: clips in `audio/cadence/` (gitignored; a real coach's voice from a broadcast clip, local use only) plus `manifest.json` with where "hut" lands. build.py inlines them (data: URIs in the standalone). A clip starts so its "hut" lands on the snap; pressing Space early plays just the hut + pads. Falls back to browser speech when there are no clips.
- Routes toggle exists for practice/tutorial; it's forced off in Today's 6 so the leaderboard is fair.
- Look controls: 1/2/3 snap the view left/middle/right; arrow keys free-look during the play; the view locks at the freeze, with only a tiny breathing sway (0.0012 rad; it was 10x larger and made placement hard).
- **Rebindable keys:** Settings → Controls (home page and pause menu). `KB_ACT` lists every action with its default (Space snap, 1/2/3 look, arrows free-look, F/T, R/P replays, M sound); bindings save to `qbcam.keys`. Binding a key that's already in use swaps the two. Esc is fixed (pause menu). Every on-screen key hint reads from `kn(action)`, so labels follow the bindings.
- **Down & distance flash:** at the start of each play `ddFlash()` punches "2nd" "&" "10" (or "Goal") onto the screen one word at a time (starts 1 s after the countdown begins, 0.42 s apart, each fades before the next lands; 3rd down gold, 4th red). Non-blocking overlay `#ddFlash`. The snap countdown is hidden while it plays (`body.ddOn`): a big "10" beside the countdown read as two timers (player report). The countdown keeps one size throughout and turns gold for the last 3 s (it used to jump to a much bigger number, which also read as a second timer).
- **Drew Bledsoe mode** (home link; user's idea): an endless story mode. Intro: a fictional newspaper ("The Foxborough Gazette", Apr 17 2000, "PATRIOTS DRAFT QB TOM BRADY") drops onto a wooden table, then 2 narration cards ("You are Drew Bledsoe." and "Hold on to your job."; the Belichick and Brady cards were removed at the user's request). Endless real plays (batches from `practicePool`, `bledFetch` tops up); the running EPA vs the pros must stay above `BLED_FLOOR` (−5.0). A job-security meter in the situation box turns amber at −2.5 and red at −3.75 with a mood line (Belichick nods / writes something down / Brady warming up / looking at the bench). At the floor the next prompt says "Coach wants a word", then a second paper ("BRADY TAKES OVER", Sep 24 2001) and the run length; best run in `qbcam.bledsoe`. Narration only, no invented quotes from the real people; routes are forced off.
- Throwing early is allowed after a 0.6 s drop.
- **Receiver tags are first initial + last name** ("J. Jefferson"; `nameTags`/`lastName` in realToPlay; suffixes like Jr. dropped), not WR1 / WR 15. In the first-person view (after the snap, outside review) tags shrink to 62% and drop to 50% opacity; full size on the overview and in review.
- **Snap banner** (`snapVerdict(diff,P,pl)`): sits over the frozen last frame of the catch cutscene (camera holds, HUD hidden via `body.held`) until the review takes over. Wins name the throw: TOUCHDOWN!, TIGHT WINDOW! (defender gap < 1.3 yd), 50/50 BALL! / 50/50… WON IT! (32+ yd, < 60% catch), ANTICIPATION! (0.4 s+ early), WHAT A DIME! (caught at < 50%), else HUGE/BIG WIN, EASY MONEY, WIN; wins fire pixel confetti in the offense's colours (`confetti()`, bigger at +0.5). Within ±0.1 is SAME READ (same target as the pro) or DEAD EVEN. Losses are low-key (smaller, grey, no red wash): Sacked, Picked off, Lucky TD / Lucky catch (a lost read that still scored or was caught at < 45%; a player complained that a TD showed as a loss), Too tight, Hope ball, Too safe, Close one, Not this time, Oof. Scoring stays on expected EPA; `outcomeNote` adds a green line when your actual result beat the pro's real one, and a lost read that was caught or scored adds "Graded on the decision, not the result: that throw is caught only N% of the time." on its own line.
- **Catch-point call** (`#cap`: Caught, Broken up, Picked off…) punches onto the upper third of the screen during the cutscene (no longer a corner caption).
- **After a play:** a tap or click on the field moves to the next play (same as Space; ignored for 0.5 s after the play ends). Phones default to a 5 s decision clock.
- **Route view (before the snap):** no situation box and no last-play box (`body.presnap`); Bledsoe mode keeps only the job-security meter there.
- **Review after a play:** no real-play card any more (`showReveal` is unused). The pro's field marker shows the QB's last name instead of PRO (`retag`), and the bottom-left panel leads with one line, "<QB> +x vs You +y EPA" (phones show only that line and the pro's-throw button). The win/loss banner holds about 4 s (over the frozen catch frame) before the review; loss/tie banners darken and slightly blur the frame so the white text reads. The next-play prompt is plain pulsing text in the middle of the screen (no box).
- **Tutorial hint:** the camera is never turned for the player. At the freeze the green ring marks the best throw among spots inside their current view (`visibleBest`), not the overall best.
- **Rank colour bands** (`bandOf`) on the results page: gold Pro Bowler and up, green Franchise QB / NFL starter / Game manager, amber Backup to College QB, red below. The big total uses the band colour, so an NFL-starter round doesn't read as a failure.
- **Touch controls (phones):** swipe left/right during the play to look around (finger right = look right); hold still ~0.23 s to pick up the ball, then drag to aim and let go to throw early. At the freeze any press aims at once (view is locked). The aim point sits 56 px above the finger and never disappears: past the field it pins to the nearest in-bounds spot along the line of the throw (`floorClamp`); dragging down onto the bottom bar (bottom 14% of the screen) and letting go cancels. Mouse keeps click-to-throw. Buttons hide keyboard hints on touch screens (`kp()`). A quick tap (under 12 px and 0.3 s) throws exactly where you tapped, at the freeze or early; press-and-drag keeps the offset aim. Phones are kept uncluttered: in first person nothing boxed is on screen (only the time-left number / "Throw now!"); the overview shows a small down-and-distance tag, the countdown and Snap now / Routes (no Throw away, Esc hint, banner or help line). Phones (`pointer:coarse` CSS) are kept minimal: no "Tap here for the next play" prompt (the bottom bar's Next play button advances), the review panel shows only the pro's-throw replay button (no stat lines, no Your throw / Run it back), and the throw-type and clock pickers are hidden (touch pass, 3 s clock).
- A receiver who has settled (curl/hitch) turns to the QB, bounces on his toes and waves; both hands go up when the ball is coming to him.

## Accounts + leaderboard (Supabase)
Google sign-in and scores use Supabase (user's choice), project `nilgjuxrbqbvsckctmxc` (set up through the Management API with `SUPABASE_ACCESS_TOKEN`). `SUPA={url,key}` at the top of the ACCOUNTS block in fp2_src.html (empty = accounts off). The anon key is public by design; `supabase/schema.sql` creates `profiles`, `rounds`, `snaps`, `daily_scores` with row-level security (own rows only; the daily board is public to read; a check constraint keeps posted scores sane). Auth settings: site URL https://pocketpasser.io, redirects allowed for pocketpasser.io, www, onrender and localhost:8000. Google OAuth client lives in the user's Google Cloud project (redirect URI `https://nilgjuxrbqbvsckctmxc.supabase.co/auth/v1/callback`). supabase-js is loaded with a dynamic `import()` from jsdelivr so a CDN failure never breaks the game.
- **Account state machine** (audited; `tests/e2e_accounts.py` covers it): auth states off / loading (`AUTH.settled` false) / guest / signed in without a username (`AUTH.named` pending) / named. `AUTH.client` is only set once the saved session is known, and `begin`/`startRound` wait for it (`afterAuth`, max 3 s), so a signed-in player never counts as a guest. One pending step at most (`PENDING`): `{type:'start',kind,arg}` from the wall or `{type:'claim',tot,wins,day}` from the results page; it runs (`runPending`) once the player is signed in and named, however the sign-in landed; it's plain data so it survives a popup-blocked full-page redirect (sessionStorage `qbcam.pending`); it's dropped when abandoned (wall "Not now", going home drops a claim, starting a round). Posting goes through `postDaily` (one path, Try again button on failure; off the results page it opens the board with the message). "Posted today" is per account (`qbcam.daily.<userId>`); the server decides. A guest can claim only this device's first Today's 6 of the day. Signing out closes the username box and releases anything waiting on it. The old round-resume-after-redirect (it re-saved the finished round) is gone.
- **Sign-in detection doesn't rely on the popup's message** (Google's pages can cut the popup off from the game window, so the claim-your-spot flow used to do nothing): `setUser` runs whatever was waiting (`runPending`) once the username exists, and `checkSignedIn` fires on a BroadcastChannel `pp-auth` ping from auth.html, the session landing in localStorage (`storage` event), window focus/visibility, or the popup's postMessage. auth.html knows it is a popup from `qbcam.authPopupAt` (set when opening it) even without an opener; it closes itself or says to go back to the game. The username sheet lives outside `#start` so it shows over the results page.
- **Sign in with Google's own button** (user's choice, so Google's screen says "continue to pocketpasser.io" rather than the Supabase project address): `signIn()` opens `#gSheet` and renders Google Identity Services' button (`accounts.google.com/gsi/client`, `GOOGLE_CLIENT_ID`); the ID token goes to `supabase.auth.signInWithIdToken` with a nonce (SHA-256 hash to Google, raw to Supabase). Needs the site's origins under Authorized JavaScript origins in the Google OAuth client (pocketpasser.io, www, http://localhost:8000, http://localhost). If Google's script is blocked, `oauthPopup()` (the Supabase OAuth popup below) is the fallback.
- **Fallback sign-in is a popup** (user's request): `signIn()` opens a window synchronously, then points it at Google (`skipBrowserRedirect`); Google returns to `auth.html?back=…`, which trades the code for a session (same-origin localStorage holds the PKCE verifier), `postMessage`s the game and closes. The game picks up the session and continues whatever the sign-in wall interrupted (`WALL_CONT`). If the popup is blocked it falls back to a full-page redirect (round saved to sessionStorage, resumes after). `auth.html` is generated by build.py from `auth_src.html` with the same `SUPA`.
- **Account button** top right of the home page (`#acctBtn`): "Sign in", or your initial + name (initial only on narrow phones), which opens the **player page** (`openMe`): career rank (tierOf average EPA per snap, band colour), tiles (snaps played, % of snaps you beat the pro, total EPA vs the pros, Today's 6 day streak), recent form (last 24 snaps as green/red bars), bests (best Today's 6, longest Bledsoe run, QBs beaten in versus, rounds finished), then **Your Today's 6**: one row per day (the first, ranked run), each opening that day's full results page read-only (`showArchive`: `S.round.archive={day}` makes `showResults` skip saving, posting, the dailyDone mark and the announcer; the board shown is that day's; the button reads Back to your stats). Rounds store their play-by-play in `rounds.res` (jsonb) for this; rows saved before it have no link. Sign out.
- **Usernames** (user's rule: never show the Google name): after the first sign-in a "Pick a username" sheet (`#unSheet`, `pickUsername`) suggests the first name (or name + digits if taken) with a live availability check (`username_available` RPC); "Skip for now" assigns Rookie_NNNN. Unique case-insensitively, 3-16 letters/digits/_ (`supabase/usernames.sql`: unique index on lower(username), format check). The database writes the board name itself (trigger on `daily_scores` insert takes the poster's username, so the browser can't post as someone else), and renaming (player page → "Change username") updates past board entries (trigger). `profiles.display_name` is no longer stored. `AUTH.named` resolves once a username exists; play resumes and scores post only after that.
- **Home Leaderboard link** (`#goBoard`, shown only when a board exists) opens today's board (top 50 + you).
- **Guest limit (user's rule):** outside the tutorial a guest gets `GUEST_ROUNDS` (2) free rounds of 6 (a Bledsoe run counts as one), counted when a round starts (`qbcam.guestRounds`); the sign-in wall (`#wall`) appears before a third round, never mid-round.
